# Architecture Overview

This document explains how all the pieces of the `next/` configuration fit together.

## The Big Picture

```
┌──────────────────────────────────────────────────────────────────┐
│  flake.nix (auto-generated)                                      │
│  - entry point for the whole config                              │
│  - generated by `nix run .#write-flake`                          │
│  - uses flake-parts + import-tree to read modules/ tree          │
└────────────┬─────────────────────────────────────────────────────┘
             │ reads
             ▼
┌──────────────────────────────────────────────────────────────────┐
│  modules/                                                        │
│  ├── dendritic.nix    ◄── framework wiring                       │
│  ├── defaults.nix     ◄── default behavior                       │
│  ├── nh.nix           ◄── nh compatibility                       │
│  ├── vm.nix           ◄── test VM                                │
│  │                                                               │
│  ├── hosts/           ◄── machine definitions                    │
│  │   ├── default.nix  ─── register all hosts + users             │
│  │   ├── kats-laptop/ ─── ThinkPad T480                          │
│  │   ├── rpi/         ─── Raspberry Pi (headless)                │
```

## How Den (the Framework) Works

Den is the framework that provides the structure. Key concepts:

### Aspects

An **aspect** is a named, composable chunk of configuration. Every file in
`aspects/` defines one or more aspects with the pattern:

```nix
den.aspects.<category>.<name> = {
  includes = [ ... ];          # other aspects this depends on
  nixos = { ... };             # NixOS-level config
  homeManager = { ... };       # home-manager-level config
};
```

Aspects can chain via `includes`. For example:
- `den.aspects.gui.gnome` includes `den.aspects.gui` (the base GUI)
- `den.aspects.gui` includes `den.aspects.gui.greetd`, `...pipewire`, etc.
- `den.aspects.base` includes `den.aspects.cli`

### Hosts and Users

Declared in `hosts/default.nix`, which tells Den:

```
┌─ Architecture ─┬─ Host name ──┬─ Users on that host ─┐
│ x86_64-linux   │ kats-laptop  │ ksakura, kat          │
│ x86_64-linux   │ wsl          │ ksakura                │
│ aarch64-linux  │ rpi          │ ksakura                │
└────────────────┴──────────────┴────────────────────────┘
```

Each host's configuration comes from `hosts/<name>/default.nix`, which
specifies which aspects to include.

### How a Build Flows

1. **`nix run .#vm`** or `nh os switch` triggers the flake
2. **`flake.nix`** loads `modules/` via `import-tree`
3. **`dendritic.nix`** tells the system to use Den's conventions
4. **`hosts/default.nix`** determines which host to build (via hostname matching)
5. **`hosts/<name>/default.nix`** lists all the aspects to compose
6. Each aspect's `includes` resolves recursively
7. The final NixOS config is built from the merged aspect tree

## Overlays Layer

The `overlays/` directory adds packages or modifies existing ones:

- **`helium.nix`** — Adds the Helium browser package to nixpkgs
- **`nil.nix`** — Pins the `nil` Nix LSP server to a specific revision

These are loaded via the `flake-file.inputs` system and applied to `nixpkgs.overlays`.

## Build Commands

| Command | What it does |
|---------|-------------|
| `nix run .#vm` | Build and launch a test VM for kats-laptop |
| `nh os switch --hostname kats-laptop` | Deploy to real hardware |
| `nix build .#nixosConfigurations.kats-laptop.config.system.build.toplevel` | Just build (no deploy) |
| `nix flake update` | Update all flake inputs |
| `nix run .#write-flake` | Regenerate `flake.nix` after adding inputs |

## File Organization Tips

- **New program?** → Add to `aspects/programs/`
- **New machine?** → Add to `aspects/hardware/` + `hosts/<name>/`
- **New network service?** → Add to `aspects/networking/`
- **New user?** → Add to `users/` + register in `hosts/default.nix`
- **New system tweak?** → Add to `aspects/system/`
- **Join things together?** → Edit `hosts/<name>/default.nix`
